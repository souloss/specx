# Core API 方向

正式机器可读契约以 `crates/specx-api` 的路由和 OpenAPI Schema 为准。本页说明资源边界和授权要求。

## 资源

| 资源 | 典型操作 |
| --- | --- |
| 工作区 | 列出、创建、改名、删除和切换 |
| 服务目录 | 查询目录树、搜索、按标签筛选和排序 |
| 目录组 | 列出、创建、改名、移动和删除空组 |
| 服务 | 创建、读取、修改、归档、恢复和带 ETag 删除 |
| 标签 | 列出、创建、改名、修改颜色和删除未关联标签 |
| 规范 | 按服务列出、创建、读取、修改、预览和带 ETag 删除 Markdown |
| 备份 | 由 owner/admin 创建、列出和恢复服务端快照 |

请求必须从认证上下文取得 tenant、主体和 workspace 权限。列表接口使用稳定排序和明确分页；写入使用幂等键或 ETag，冲突不能静默覆盖其他主体的内容。

浏览器写请求采用同源部署，并在配置 `SPECX_PUBLIC_ORIGIN` 时按公开 origin 校验来源。无浏览器 Origin 的服务端客户端仍需通过可信认证上下文授权。

错误统一使用 v1 envelope；HTTP status 表达协议结果，唯一的 `snake_case` 错误码表达具体机器身份。完整字段、code 命名和新增错误要求见[API 错误契约](../architecture/api-error-contract.md)。备份只能引用服务端生成的当前作用域文件，客户端不能提交任意路径。
