# 一期存储策略

Core 保存租户、工作区、服务、目录、标签、规范元数据、授权关系以及外部同步所需的内容引用和快照元数据。SQLite 适配器用于本地开发和单机 Docker 部署；`SPECX_DATABASE_URL` 使用 `sqlite://` 时继续选择 SQLite，使用 `postgres://` 或 `postgresql://` 时选择 PostgreSQL，以支持共享部署。两种适配器通过同一组 API 操作。

物理内容由平台内部 `ContentStore` 统一选择。平台根据部署配置、内容类型、大小和生命周期，将规范正文、附件、仓库快照和分析产物放入 SQLite 内嵌内容、文件系统或对象存储；普通用户不选择 StorageClass，也不在业务资源中配置存储后端。Core 和控制器只保存 `ContentRef`、content hash、大小、媒体类型、保留策略和恢复所需元数据。缓存不可成为唯一事实。

控制器通过 ContentStore 写入或读取内容，Provider 不直接连接 Core 数据库。仓库控制器产出的不可变快照和 Markdown 控制器追加的规范修订都必须带内容 hash 和来源证据；事件或缓存丢失后，可以依据资源绑定和快照元数据重新协调。

## 备份

本地快照写入 `SPECX_BACKUP_ROOT`，默认是数据目录下的 `backups`。备份路径由服务端生成，API 只返回当前租户/工作区作用域的文件，恢复要求 owner 或 admin。PostgreSQL 共享部署使用其对应的备份适配器和应用层加密配置；密钥由部署平台注入，不写入仓库或镜像。

## 约束

- 每张业务表带租户和工作区作用域，数据库角色和应用授权同时校验。
- 目录通过父节点引用并在应用层防止循环；删除前处理子目录或服务引用。
- 标签关系使用显式关联表，标签重命名不改变服务身份。
- 规范保存内容摘要和类型；启用修订时，历史只追加不覆盖。物理内容由 ContentStore 管理，资源只保存引用和校验信息。
- 已执行迁移不可原地改写。

创建服务、目录移动、标签修改和规范元数据更新在 Core 事务中完成。渲染和备份可以在事务外执行，但结果必须关联资源和内容版本。
